# Provider: YouTube Music

- Tier: 2 (unofficial use of a commercial service's endpoints)
- Endpoint: `music.youtube.com` / `youtubei` endpoints, reached through InnerTubeX (see [innertubex.md](innertubex.md))
- Owner: Google (no relationship with Aria)
- Default: on (the app cannot work without it)
- Kill switch: registry key `killSwitches.youtube` (data only). Status: the registry schema and signature verifier exist in `:core`; nothing in the app fetches the registry or reads this key yet, so the switch is not operable today.
- Fallback: none. Planned behaviour is to show "YouTube Music is unavailable" and keep downloaded and local tracks playable; neither the message nor downloads exist in the walking skeleton.
- Data sent: search queries, video IDs, and the device/client identifiers the client library sends
- When: on search and on playback only; no background calls from the foundation
- Opt-in: not applicable (core feature). To be disclosed in first-run text and in [PRIVACY.md](../../PRIVACY.md); first-run text is not built yet, PRIVACY.md covers it for now.
- PoToken generator: some streams need a web-client PoToken. `WebViewPoTokenSource` (package `app.aria.innertube.potoken`, ported from Meld, see `docs/provenance.csv`) mints them with BotGuard in a hidden, confined WebView (ADR-0002: never attached to a window, `NavigationPolicy` allows only `about:blank` and the `https://www.youtube.com` base-URL document, `blockNetworkLoads = true`, no file or content access, no third-party cookies, exactly one string-only JavaScript bridge, every token validated, WebView destroyed after each batch, one WebView at a time, 15 s timeout; `scripts/check-webview-safety.sh` enforces the confinement in CI). Kotlin (not the WebView) POSTs to `https://www.youtube.com/api/jnn/v1/Create` and `.../GenerateIT` with `java.net.HttpURLConnection` through `YouTube.proxy`, sending visitor data and the BotGuard request; no Aria server is involved. Constants kept from Meld: the BotGuard `REQUEST_KEY` `O43z0dpjhgX20SCx4KAo`, a Google web API key sent as `x-goog-api-key` (`AIzaSyDyT5W0Jh49F30Pqqtyfdf7pDLFKLJoAnw`) and a spoofed desktop Chrome 131 `User-Agent`. Changes from Meld: the page's JavaScript bridge was reduced from six methods to one, OkHttp and `YouTube.proxy` replaced by `HttpURLConnection` and an injectable proxy hook, WebView kept per batch instead of per session. Status: **stays open until the maintainer confirms playback on a device** (the WebView cannot be exercised in unit tests or CI).
- Stream extractor: `ExtractorSession` (package `app.aria.innertube.extraction`) builds the InnerTubeX `InnerTubeExtractor` on the shared HTTP transport and is rebuilt when that transport is replaced. `InnerTubeXAudioExtractor` asks for direct audio only (no HLS, no SABR; a SABR result is treated as unavailable) at the highest audio quality. `YouTubeStreamSource` rejects any stream URL that is not `https://`, and gives a URL without an expiry a 5-minute lifetime. A client whose stream was rejected is remembered for 5 minutes and excluded on the next resolve (`FailedClientMemory`). It makes the player requests to YouTube that the library makes for the web and fallback clients, and fetches the watch page (or the embed page as a fallback) for the player configuration. Playback itself then reads the returned `googlevideo` URL.
- Cipher config: disabled. `AriaPlayerConfigRepository` reports `enabled = false` with empty URLs, so InnerTubeX builds no remote config store and never fetches a player config; it uses its built-in solver. `CipherConfigUpdater` and the signature check in `:core` (`CipherConfigVerifier`, Ed25519) exist and are tested, but the app does not run the updater and embeds no production key. A verified config could be kept on disk (`FileCipherConfigStore`), but InnerTubeX v0.5.2 has no way to take it, so nothing reads it. No cipher config is bundled. Enabling it is an open gate in [release-gates.md](../release-gates.md).
- Radio: `YouTubeRadioSource` calls the YouTube Music `next` endpoint with the seed video ID and the playlist ID `RDAMVM<video id>`, removes the seed from the result and returns up to the requested number of tracks. Same endpoint family and data as search and playback; no third-party service. It runs when the endless-radio toggle is on (the default), repeat is off and the queue is running out; results are added in batches of 25.
- Return YouTube Dislike: the Meld code this module was ported from called `returnyoutubedislikeapi.com` from `getMediaInfo` to fetch view, like and dislike counts. Aria's port intentionally drops that call (and the `viewCount`/`like`/`dislike` fields of `MediaInfo`): it is a different third party that receives the video ID and the device's IP address, and it has no provider record. Any third-party endpoint needs its own record in `docs/providers/`, a row in [data-flow.md](../data-flow.md) and a matching [PRIVACY.md](../../PRIVACY.md) entry before code that calls it is added.
